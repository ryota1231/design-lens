## 0. ビジョン / プロダクトの根本目的（Why）

### 0.1 なぜこのアプリを作るのか

AI の発達により、誰でも「それらしい」デザインを作れる時代になった。
しかし AI に任せきりで生み出されたデザインには、**「なぜこのデザインなのか」という作り手の意図**が乗っていない。

これからの時代、強いのは：

> **デザインの意図を持って、AI を使いこなせる人。**

Design Lens は、その力を**誰でも自然に身につけられる**ように設計された学習アプリである。
街中の優れたデザインに毎日触れ、その意図を AI と一緒に言語化することで、ユーザー自身の中に「意図を持つ目」が育っていく。

### 0.2 アプリが目指すユーザー変容

| 観察前 | 観察後 |
|--------|--------|
| AI に頼んで出てきたものを、なんとなく良し悪しで判断する | このデザインが「なぜ・どう機能しているか」を言語化できる |
| 自分が作りたいものをAIにうまく説明できない | 意図を踏まえた具体的なプロンプトを書ける |
| デザインを「センス」の問題と感じている | デザインを「観察できる構造」として捉えられる |

### 0.3 設計原則として宣言すること

- **意図を主役にする**: 解析結果のすべての要素は、「設計意図を実現する手段」として読めるよう構成する
- **馴染みやすさを最優先する**: 専門用語ばかりで威圧しない。誰でも入っていける言葉で語る
- **押し付けない**: AIの解析を「正解」とは言わず、「観察と推測」として提示する

## 1. プロダクト概要

街中で見かけた看板・ロゴ・POP・サイネージなどのデザインをスマートフォンで撮影すると、AI（Claude Vision）がデザインの**意図**と要素を即座に言語化し、再現プロンプトや類似デザイン検索まで一気通貫で提供するアプリ。

「観察 → 解析 → 蓄積 → 創造」のサイクルを日常の街歩きに組み込み、移動時間そのものを**「意図を持つ目」を育てる時間**へ転換することを目指す。

> 日常を、クリエイティブの実験室に。

### 1.1 リリース戦略

1. **Phase 1（Webサービス版）**: PWAとして先行リリース。Next.js + React で実装し、カメラ入力に対応。
2. **Phase 2（ネイティブアプリ）**: TestFlightクローズドβ → App Store本番公開。

## 2. 課題と提供価値

| 観点 | Analog Reality（現状の課題） | Design Lens Reality（アプリで実現すること） |
|------|------------------------------|---------------------------------------------|
| **Time** | 移動時間が無駄に。通勤・外出時間がただ消費される | 街歩きが自動学習時間に。1日1枚の撮影で、年365件の資産へ |
| **Skill** | 「いいデザイン」を言語化できない。感性で終わり、理由が分からない | AIが「良さ」を瞬時に言語化。配色・構図・コンセプトを論理的に解説 |

## 3. コア機能

### 3.1 ワンタップ撮影 → 即時解析（Powered by Claude Vision）

撮影したデザインを以下の観点で自動解析する。

- **コンセプト**: デザインの意図・狙い（例: 緊急性と高揚感を煽る、セール訴求デザイン）
- **タイポグラフィ**: 使用フォントの傾向（例: 極太サンセリフ / 視認性最大化）
- **配色**: 主要カラーのHEXコード抽出（例: #FF0000, #FFFF00, #000000）
- **構図・ターゲット**: 視線誘導、想定ターゲット層

### 3.2 再現プロンプトの自動生成

「このデザインを自分で作るなら」のAI生成プロンプトをワンタップで取得。
ユーザーは取得したプロンプトを DALL-E / SDXL 等の画像生成AIに投入することで、デザインを再構築できる。

### 3.3 類似デザインの瞬時検索（コンセプト類似ベース）

**方針**: 視覚類似（リバースイメージサーチ）ではなく、**コンセプト類似**による検索を採用する。

#### 採用しないアプローチとその理由

| アプローチ | 採用しない理由 |
|------------|----------------|
| Pinterest 連携 | 公式APIが検索機能をほぼ提供していない。スクレイピングは規約違反リスク |
| Google Reverse Image Search | 公式APIが2011年に廃止済み。Google Lens APIも非公開 |
| Bing Visual Search | 視覚類似は実現可能だが有料（$4〜7/1000クエリ）。MVPではコスト面でスコープ外 |

#### 採用する実装方式

1. Claude Vision で撮影画像を解析 → **特徴キーワードを抽出**
   - 例: `["極太サンセリフ", "セール訴求", "赤黄黒の三色構成", "緊急性"]`
2. 抽出キーワードを使って **Exa API / Unsplash API 等** をテキスト検索
3. 結果から関連性の高い事例を **5〜10件抽出**してユーザーに提示
4. UI上で「**コンセプトが近い参考事例**」と明示（視覚類似ではないことを誤認させない）

**メリット**: 完全無料枠で実装可能 / 著作権・規約リスクが低い / 「なぜこの事例が出たか」を言語化できるためユーザーに学習効果がある

**割り切り**: 画像のピクセルレベルでの類似性は提示しない（必要になった段階で将来拡張）

### 3.4 パーソナルデザイン図鑑（永続資産化）

撮影したデザインをカテゴリ別に自動分類・保存。

- **カテゴリ例**: 看板 / ロゴ / POP / サイネージ
- **フォント分類例**: 極太サンセリフ、Sans-Serif、明朝体、手書き風、Digital Grotesque
- **目標**: 1日1枚で年365件のナレッジ蓄積

検索・フィルタ機能により、過去の撮影物からインスピレーション素材を即時取り出し可能。

### 11.3 データフロー（撮影 → 解析 → 保存）

```
[ユーザー] ─tap─→ [撮影ボタン]
                    ↓
              [カメラ起動 (getUserMedia)]
                    ↓
              [撮影 → Canvas で 1024px に圧縮]
                    ↓
              [base64エンコード]
                    ↓
              [POST /api/analyze { image, lang }]
                    ↓
              [Rate Limit チェック（IP/セッション）]
                    ↓
              [Anthropic SDK → Claude Vision]
                    ↓
              [JSON 解析結果を返却]
                    ↓
              [IndexedDB に保存: { id, image_blob, analysis, created_at }]
                    ↓
              [解析画面表示（再現プロンプトはここで二次取得）]
```

### 11.4 データモデル（IndexedDB）

```typescript
// IndexedDB schema (Dexie.js)
interface Photo {
  id: string;                  // UUID
  blob: Blob;                  // 圧縮済み画像（〜1024px長辺）
  thumbnailBlob: Blob;         // サムネイル（〜256px）
  createdAt: number;           // unix epoch ms
}

interface Analysis {
  id: string;                  // UUID
  photoId: string;             // Photo.id への外部キー
  concept: string;             // コンセプト（例: 緊急性と高揚感を煽る、セール訴求）
  typography: string;          // タイポグラフィ説明
  fontHints: string[];         // 推定フォント候補
  colors: Array<{ hex: string; role: string }>; // 配色（HEX + 役割）
  composition: string;         // 構図・視線誘導
  target: string;              // ターゲット層
  extractedText: string[];     // OCR抽出テキスト
  category: 'sign' | 'logo' | 'pop' | 'signage' | 'other'; // カテゴリ
  language: 'ja' | 'en';       // 解析結果の言語
  rawResponse: string;         // Claude の生レスポンス（デバッグ用）
  createdAt: number;
}

interface ReproductionPrompt {
  id: string;
  analysisId: string;
  prompt: string;              // 再現用プロンプト本文
  createdAt: number;
}
```

### 11.5 API設計

#### `POST /api/analyze`

リクエスト:
```json
{
  "image": "data:image/jpeg;base64,...",
  "language": "ja"  // "ja" | "en"
}
```

レスポンス:
```json
{
  "concept": "緊急性と高揚感を煽る、セール訴求デザイン",
  "typography": "極太サンセリフで視認性最大化",
  "fontHints": ["Impact", "Helvetica Black"],
  "colors": [
    { "hex": "#FF0000", "role": "primary / 訴求色" },
    { "hex": "#FFFF00", "role": "accent / 注意喚起" },
    { "hex": "#000000", "role": "text / 強コントラスト" }
  ],
  "composition": "中央配置 / 視線が大きな数字に集まる構図",
  "target": "通行人 / 即時購買意欲のある層",
  "extractedText": ["SALE", "50%", "OFF"],
  "category": "pop",
  "rawResponse": "..."
}
```

エラー:
- `400`: 画像なし / フォーマット不正
- `429`: レート制限超過
- `500`: Claude API エラー

#### `POST /api/prompt`

リクエスト:
```json
{
  "analysisId": "uuid",
  "analysis": { /* Analysis オブジェクト */ },
  "language": "ja"
}
```

レスポンス:
```json
{
  "prompt": "極太サンセリフで「SALE 50% OFF」と中央配置、#FF0000を主色に..."
}
```

### 11.6 エラー処理方針

| エラー種別 | 対応 |
|------------|------|
| カメラ権限拒否 | ガイダンス表示「設定 → サイト権限でカメラを許可してください」 |
| ネットワークエラー | 撮影画像は IndexedDB に「未解析」として保存、後で再試行ボタン |
| Claude API エラー | ユーザーに「AI解析に失敗しました」表示、原因コードをログ |
| IndexedDB 容量不足 | 古い画像を削除する提案ダイアログ |
| レート制限超過 | 残量と再開可能時刻を表示 |

### 11.7 UI / UX 原則（馴染みやすさの担保）

ビジョン（セクション 0）の「**馴染みやすさを最優先する**」を具体化するため、以下を実装上の規約として徹底する。

- **両方併記の原則**: 専門用語を出すときは必ず日常語と併記する。
  - 例: `ヒゲのない太い文字（極太サンセリフ）`
  - 例: `画面の真ん中に大きく置く構図（センター強調レイアウト）`
  - 例: `警告を連想させる色の組み合わせ（赤＋黄のコントラスト配色）`
- **「正解」を避けるトーン**: 解析結果のラベルは「AIの解釈」「観察と推測」と明示する。
- **意図ファースト**: 解析画面ではまずユーザーの目に「設計意図」が入り、その後で配色・タイポなどの要素が現れる視覚順序にする（データ構造はフラットでも、表示順序で意図を優先）。
- **専門用語の参照導線**: 専門用語にはツールチップ／脚注で短い説明を添える（実装は Phase 1 で最低限のもので可）。
- **言語切替**: 日本語 ⇄ 英語 でこの原則は同じ。英語表記の場合も `Bold sans-serif (thick fonts without serifs)` のように両方併記する。

### 11.8 セキュリティ

- **APIキーは絶対にクライアントに露出させない** — `ANTHROPIC_API_KEY` はサーバ環境変数 (`.env.local` / Vercel Environment Variables) のみ
- **画像はサーバに永続化しない** — API Routes は受け取った画像をClaude APIに転送するのみ、保存しない
- **匿名利用のレート制限** — IP単位で 1時間に 20リクエスト程度の制限（個人開発のコスト保護）
- **CSP（Content Security Policy）** — XSS対策

| 単体 | Vitest | ユーティリティ（画像圧縮、Zod validator、Dexie wrapper）|
| 統合 | Vitest + msw | API Routes（モック化したClaude API）|
| E2E | Playwright | 主要フロー（撮影 → 解析 → 保存 → 一覧表示）|
| 視覚回帰 | Chromatic（任意） | UIコンポーネントのスナップショット |

TDD原則: 撮影〜保存の主要ロジックは先にテストを書く。Claude API呼び出しは msw でモック。
