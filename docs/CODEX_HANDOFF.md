## 3. 進め方の選択肢

### Option A: タスクごとにレビュー（推奨・安全）

各タスク完了後に動作確認・レビューを挟む方式。Codex とのやり取りが多くなるが、早期に方向性のズレを修正できる。

**プロンプト例（タスク完了後）:**
```
Task 1 の実装、確認しました。問題ないので Task 2 に進んでください。
```

または問題があれば：
```
Task 1 の Step 1.2 で .DS_Store を含めてしまっているようです。git rm --cached で除外し、.gitignore に追加してから再コミットしてください。
```

### Option B: 連続実行（速いが要注意）

数タスクをまとめて実装してもらい、まとまった単位でレビュー。クレジット消費は抑えられるが、軌道修正が遅れる。

**プロンプト例:**
```
Task 1 から Task 5 までを連続で実装してください。各タスクで TDD と git commit を必ず守り、テストが落ちたら必ず修正してから次へ進んでください。完了後にまとめて報告してください。
```

### Option C: フェーズ単位

実装計画書を以下のフェーズに分けて、フェーズ単位で進める：

| フェーズ | タスク | 完了時の確認ポイント |
|----------|--------|---------------------|
| **基盤** | Task 1-2 | `pnpm dev` で Next.js デフォルトページが表示される、`pnpm test` でサニティテストがパス |
| **コアロジック** | Task 3-7 | 型・DB・画像処理・レート制限のテストがすべてパス |
| **AI 統合** | Task 8-10 | `/api/analyze` `/api/prompt` のテストがパス（モック使用） |
| **i18n + UI 基盤** | Task 11-12 | `/ja` `/en` で言語切替が動く |
| **画面** | Task 13-16 | カメラ→撮影→解析→保存→閲覧の通しが動く（要 ANTHROPIC_API_KEY） |
| **仕上げ** | Task 17-21 | PWA インストール可、E2E パス、README 完成 |

## 4. Codex とのやり取りで効果的な指示の出し方

### ✅ よい指示
- 「Task 8 から Task 10 を実装してください。各タスクで TDD を守り、`pnpm test` がパスすることを確認してからコミットしてください」
- 「Task 14 で `useCamera` フックの実装が完了したら、`pnpm test useCamera` の結果を貼り付けて報告してください」
- 「現在の `src/lib/db/repository.ts` を見せてください」

### ❌ 避けたい指示
- 「いい感じに進めてください」（曖昧）
- 「もっとよいライブラリがあれば使ってください」（スコープ逸脱の元）
- 「テストは後でまとめて書いてください」（TDD原則違反）

### 💡 行き詰まったとき
- Codex が「ライブラリのバージョン差で動かない」と言ったら、`package.json` のバージョンを実装計画書通り（next 15, react 19等）に固定して再試行を依頼
- 既存ファイルの内容を見たいときは「`src/app/[locale]/page.tsx` の現在の内容を全文見せてください」
- 大きく道を外れた場合は「`git diff` で直近の変更を見せて、何を変えたか説明してください」

`.env.local` の設定はユーザー自身が行ってください。Codex には**キー本体を渡さない**こと。

## 7. Vercel デプロイ手順（実装完了後）

Codex に頼んでも、ユーザー自身でやってもどちらでも OK。

1. GitHub にこのリポジトリを push（`feature/phase1-mvp` を main にマージしてから）
2. https://vercel.com/new で GitHub リポジトリを Import
3. Framework Preset は **Next.js** が自動検出される
4. **Environment Variables** に `ANTHROPIC_API_KEY` を設定（本番用キー）
5. Deploy ボタンを押す
6. ビルド成功後、発行された URL をスマホで開く
7. PWA としてホーム画面に追加するアイコンが出れば成功

## 8. トラブル時のフォールバック

- **Codex が複数タスクで詰まる** → タスクを 1 つずつに分割して指示
- **テストが大量に失敗** → Task 番号を指定して「この Task のテストだけ通してください」
- **設計判断に迷う** → 仕様書を引用しつつ「仕様書 11.X に沿うとどう実装すべきですか？」と問う
- **道を外れる傾向** → AGENTS.md の「してはいけないこと」を再提示
- **どうしても進まない** → 残タスクを後回しにして、動く MVP（撮影→解析→表示）を先に完成させる
